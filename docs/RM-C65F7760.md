# Minicore VFS 구조

VFS 경로가 구현될 때마다 이 문서에 기록한다(설계자 지시, 2026-09-14
- CLAUDE.md 규칙에도 명시). SP-8B6B8D25 §4(파일 시스템 구조)/§4-A
(VFS 루트 소유권)가 정한 큰 그림 안에서, **실제로 코드로 구현된
경로만** 여기 적는다 - 설계 문서의 계획 트리 전체가 아니라 "지금 진짜
동작하는 것"의 현황판이다.

## 구현된 경로

| 경로 | 구현 위치 | 설명 | 상태 |
|---|---|---|---|
| `/sys/live/named/<name>` | `minicore/kernel/named_object.h/.cpp` | 이름 있는 IPC 오브젝트(메시징 채널 등) 네임스페이스(SP-1FBC0EEB) - 실제 파일 테이블 자체는 커널 내부(`NamedObjectTable`, PL-C8648D4D 완료). **[개정, 2026-09-15]** 라우팅은 더 이상 커널의 특수 경로 우회가 아니라 `/sys/live` 전체에 마운트되는 `livefs`(`KernelFsDriver` 구현, SP-7CC5693A §2.4)를 거친다 - `livefs`가 `named/` 하위 경로를 `NamedObjectTable`에 위임 | 구현 완료(스토리지는 커널 내부 테이블) + 라우팅은 livefs 재배선 설계 완료(SP-7CC5693A §2.4, 아직 미구현) |

## 아직 구현 안 된 경로 (SP-8B6B8D25 §4 설계상의 나머지)

`/boot`, `/sys/etc`, `/sys/bin`, `/sys/mnt`, `/sys/dev`, `/sys/tmp`,
`/apps`, `/run`, `/usr/{사용자명}/*`, `/home/{사용자명}` - 전부 `fs`
서비스(유저랜드, `minicore/fs`, 관련 계획 PN-71C2B857 등)가 실제로
구축될 때 하나씩 이 문서에 추가한다.

**예외 - `/sys/live/initrd.cpio`**(설계자 지시, 2026-09-15,
PN-71C2B857): `/sys/live/named/`와 같은 마운트인 **livefs**(`/sys/live`
에 마운트되는 커널 자체 구현 `KernelFsDriver`, SP-7CC5693A §2.4)의
두 번째 하위 경로로 계획됨 - `fs` 서비스 구축을 기다리지 않는다.
CPIO를 실제 파일시스템으로 마운트하지 않는다 - initrd 이미지 전체를
**하나의 불투명한 파일**로만 노출한다(내부 엔트리를 디렉터리 트리로
풀어 보여주지 않음). 아직 미구현(현재는 부팅 시 진단 로그까지만).

**예외 - `/sys/live/kernel/<devmgr|fs|net|tty>`**(설계자 지시,
2026-09-16, SP-00CA7175 §2.0 최종안 - 두 세션의 동시 개정을 병합한
버전으로 아래 §2 Tier B 설명을 대체함): 단순 `NamedObjectTable` 재사용이
아니라 전용 `KernelReservedTable`(`minicore/kernel/livefs.h`)을 새로
둔다 - 부팅 시 `kmain.cpp`가 `KernelReservedTable::reserveForKernelService()`
를 호출해 4자리를 선점하는 것은 이전 안과 같지만, **`LiveFs::open()`이
그 경로를 열 때마다 매번 `ProcessRole == KernelService`이고 스폰 이름이
정확히 일치하는지 검사**한다. 순수 `NamedObjectTable::reserve()`만으로는
부팅 시 선점 자체는 막되 이후 어떤 프로세스가 문자열
"kernel/devmgr" 같은 이름을 알아내 `connectChannel()`로 연결하는 것까지는
막지 못하는 틈이 있었다(Channel 이름 연결에는 소유자 ACL이 없는 기존
관례, SP-0666DB3C §17.3 Mutex와 동일) - `KernelReservedTable` +
`LiveFs::open()` 검사가 이 틈을 닫는다. 라우팅 경로 자체(상대 경로를
그대로 조회 키로 넘기는 것)는 `/sys/live/named/`와 동일하되, 조회 대상이
`NamedObjectTable::resolve()`가 아니라 `KernelReservedTable::find()` +
권한 검사인 점만 다르다. 아직 미구현(livefs 자체도 미구현,
PN-71C2B857) - 구현 시점에 이 항목을 "구현됨"으로 갱신(PN-7AC01E6E
항목 6).

## 기록 규칙

- VFS 경로 하나가 실제 코드로 동작하기 시작하면(진짜 마운트 지점이든,
  `/sys/live/named/`처럼 그 전 단계의 임시 내부 구현이든) 이 문서의
  "구현된 경로" 표에 행을 추가한다.
- "상태" 칸에 "진짜 VFS/`fs` 서비스를 통한 구현"인지 "그 전 단계의
  임시 내부 구현"인지를 명시한다(`/sys/live/named/` 선례처럼).
