# Minicore VFS 구조

VFS 경로가 구현될 때마다 이 문서에 기록한다(설계자 지시, 2026-09-14
- CLAUDE.md 규칙에도 명시). SP-8B6B8D25 §4(파일 시스템 구조)/§4-A
(VFS 루트 소유권)가 정한 큰 그림 안에서, **실제로 코드로 구현된
경로만** 여기 적는다 - 설계 문서의 계획 트리 전체가 아니라 "지금 진짜
동작하는 것"의 현황판이다.

**[정리, 2026-09-26, 설계자 지시]** 이 문서가 각 경로마다 그동안의
갱신/정정 이력을 층층이 쌓아 두어 읽기 어려워졌다는 지적을 받아,
현재 상태만 간결하게 남기고 지나간 경위(몇 번 갱신됐는지, 과거에
뭐라고 잘못 적혀 있었는지)는 전부 제거했다 - 이 문서는 감사 로그가
아니라 "지금 이 순간의 현황판"이라는 원 취지에 맞춘 것이다. 과거
경위가 필요하면 각 행이 인용하는 `PN-`/`commit` 추적코드로 그
계획 문서를 따라가면 된다.

## 구현된 경로

| 경로 | 구현 위치 | 설명 | 상태 |
|---|---|---|---|
| `/sys/live/named/<name>` | `named_object.h/.cpp` + `livefs.h/.cpp`(`LiveFs::open`) | 이름 있는 IPC 오브젝트(메시징 채널 등) 네임스페이스(SP-1FBC0EEB) - `NamedObjectTable`(`PL-C8648D4D`)에 위임 | 완료 - Open/Read 등 표준 파일 syscall(그룹3)로 유저 프로세스가 직접 사용 가능 |
| `/sys/live/initrd.cpio` | `livefs.h/.cpp`(`captureCpioArchive`/`open`/`read`) | CPIO initrd 이미지 전체를 하나의 불투명한 파일로 노출 | 완료 + 실측 검증(4개 QEMU 시나리오) |
| `/sys/live/kernel/<devmgr\|fs\|net\|tty>` | `livefs.h/.cpp`(`KernelReservedTable`) | 커널↔커널서비스 통신 채널(SP-00CA7175) 예약 지점 - `ProcessRole::KernelService`+스폰 이름 일치 검사 | 코드 구현 완료 - 인증 성공/거부 분기의 실제 실측은 아직 없음(존재하지 않는 이름의 NotFound만 확인, 실사용처 등장 시 재검증) |
| `/sys/live/proc/<self\|pid>/status` | `procfs.h/.cpp`(`ProcFs`) | 호출자 자신 또는 임의/자식 pid의 상태(Pid/ParentPid/Role/Zombie/ThreadState) 텍스트 뷰(SP-5D965B74) - pid 대상은 부모/자신/KernelService만 허용 | `self`는 완료+실측(size=87, syscall 왕복 확인). `<pid>` 일반화는 구현+회귀 검증 완료, 다만 권한 4케이스(자기/권한있음/권한없음/경쟁) 실측은 실제 `SpawnProcess` 사용 사례가 없어 `PN-012D6310`으로 대기 |
| `/sys/live/resourcegroup/<name>/cpu.stat`, `/memory.stat`, `/io.stat` | `resource_group.h/.cpp`(`ResourceGroupFs`) | 그룹의 CPU/메모리/IO 쿼터+계정 텍스트 뷰(SP-6A563A8F/SP-A21DD889) - 핸들은 그룹 포인터에 파일별 태그 비트를 얹어 인코딩 | 셋 다 완료 - open/read/stat + 실제 유저랜드 syscall(Open/Read/Close) 왕복까지 실측 검증(`PN-4190BBD3`/`PN-A40787C8`/`PN-A032862F`) |
| `/sys/etc`, `/sys/bin`, `/sys/tmp` | `fs.cpp`(`PN-452FF696` 항목3) | `fs` 커널서비스(`KernelThread`, `PN-D6A05E78`)가 부팅 시 `MountKind::Channel`로 등록 | 마운트 테이블 라우팅만 완료 - `Open`이 `NotSupported` 반환(Channel 마운트의 IPC 와이어 포맷이 아직 미정, `SP-2AAD7C8D` §9.1) |
| `/sys/mnt` | `fs.cpp`(`kTryAutoMountBlockDevice()`, `PN-452FF696` 항목5) | 부팅 시 AHCI 블록 장치 감지되면 우선순위(ext4 → FAT32 → FAT12/16)로 슈퍼블록 판별 후 `MountKind::KernelDriver`로 마운트 | 완료 + 실측(첫 진짜 디스크 E2E, `commit 8ffadde`). ext4/FAT32/FAT16 전부 읽기+쓰기 지원, ext4는 jbd2 저널 리플레이(`PN-BC3A2F5F`)와 익스텐트 트리 depth 0→1 확장(`PN-81C6322C`)까지 구현+검증됨. exFAT/NTFS(`ExfatDriver`/`NtfsDriver`, 구현은 존재)는 이 자동 감지 순서에 아직 미포함 |

## 아직 구현 안 된 경로 (SP-8B6B8D25 §4 설계상의 나머지)

`/boot`, `/sys/dev`, `/apps`, `/run`, `/usr/{사용자명}/*`,
`/home/{사용자명}` - `/sys/dev`는 devmgr 담당(fs 범위 밖), `/boot`는
UEFI 경로 전용(레거시 BIOS 직접 부팅은 설계자 지시로 불필요 확정,
`PN-FC1D92DA`), `/usr/{사용자명}/*`는 사용자 계정 모델 자체가 아직
없어 skip - `/apps`/`/run`/`/home`은 SP-8B6B8D25 §4의 트리 문서상
존재하나 명시적으로 "일반 FS 마운트 지점"으로 태그되지 않아(오버레이/
별칭 개념에 가까움) 별도 설계 확정이 필요할 수 있다. 전부 필요해지는
시점에 하나씩 이 문서에 추가한다.

**남은 공백**: `MountKind::Channel`(`/sys/etc`/`/sys/bin`/`/sys/tmp`)
의 `Open`이 여전히 `NotSupported` - 그 IPC 와이어 포맷이 아직
미정(`SP-2AAD7C8D` §9.1), `fs` 서비스가 실제로 그 프로토콜을 쓰기
시작할 때 확정 필요.

## 참고

- 표준 파일 syscall(`Open`/`Close`/`Read`/`Write`/`Stat`/`Mkdir`/
  `Unlink`, `SP-2AAD7C8D` §9.3, `RM-48E1E610` 그룹3)은 `MountKind::
  KernelDriver`로 마운트된 모든 경로(named/kernel/initrd.cpio/proc/
  resourcegroup/mnt)에 공통으로 적용된다 - 개별 경로마다 별도
  syscall이 필요하지 않다.
- 소켓 계층(`SP-231493CB`, review)이 `/sys/live/named/<pid>/<handle>`/
  `/sys/live/named/unix/kernel/0/<handle>` 자동 등록 경로를 이
  네임스페이스 위에 추가할 예정 - 승인되면 이 문서에도 행을 추가.

## 기록 규칙

- VFS 경로 하나가 실제 코드로 동작하기 시작하면(진짜 마운트 지점이든,
  `/sys/live/named/`처럼 그 전 단계의 임시 내부 구현이든) 이 문서의
  "구현된 경로" 표에 행을 추가한다.
- "상태" 칸은 **현재 상태만** 간결하게 적는다 - 갱신/정정 이력을
  층층이 쌓지 않는다(2026-09-26 설계자 지시). 과거 경위가 필요하면
  그 행이 인용하는 `PN-`/`commit` 추적코드를 따라간다.
