## 0. 배경

`PN-D168A778`(libext4 6차 증분 - RO_COMPAT_QUOTA, completed)이
사용자 쿼터(`usrQuotaInum`)의 하드리밋 체크(1단계)/curspace 증분
(2단계)/curspace 감소(3단계)를 구현·실측 검증까지 완료했지만, 다음
세 가지는 시작부터 명시적으로 범위 밖에 남아 있었다:

1. **그룹 쿼터**(`grpQuotaInum`) - 처음부터 미착수.
2. **트리 삽입** - 아직 quota v2 트리에 없는 uid/gid의 첫 쓰기 시
   새 리프 엔트리를 만드는 것(리프 포화 시 분할까지) - 지금 코드는
   "트리에 없으면 그냥 건너뛴다"(무제한 관례)로만 처리.
3. **curinodes**(inode 개수 쿼터) - 지금 배선은 블록(공간) 쿼터만
   다루고, inode 생성/삭제에 따른 개수 카운트는 손대지 않았다.

## 1. 설계 A - 그룹 쿼터

### 1.1 핵심 통찰 - 새 자료구조가 필요 없다

리눅스 quota v2 온디스크 포맷은 사용자/그룹 쿼터가 **완전히 독립된
별도 파일**(각자 다른 inode - `usrQuotaInum`/`grpQuotaInum`)에
**동일한 구조**(`QuotaV2Header`/`QuotaV2Info`/`QtreeLeafHeader`/
`QuotaV2DiskDqblk`, `ext4.h`에 이미 정의됨)를 담는다. 이미 구현된
`kQtreeDepth`/`kQtreeGetIndex`/`kQtreeFindEntryInLeaf` 순수 함수는
"어떤 inode를 열지"와 무관하게 그대로 재사용 가능하다 - 달라지는
건 (a) 어느 inode를 여는지, (b) 키로 uid 대신 gid를 쓰는지뿐이다.

### 1.2 구현 방향

1단계(하드리밋)/2단계(증분)/3단계(감소)가 각각 만든 3개 함수(또는
그 안의 quota 트리 순회 블록)를 `quotaInum`+`id`(uid 또는 gid)를
매개변수로 받는 공용 헬퍼로 리팩터한다:

```
errno_t kExt4QuotaCheckHardLimit(quotaInum, id, projectedBytes);
void    kExt4QuotaAdjustCurspace(quotaInum, id, deltaBytes);  // 양수=증가, 음수=감소
```

Write/Unlink 경로는 이제 이 헬퍼를 **usrQuotaInum+제출자uid**와
**grpQuotaInum+제출자gid** 양쪽에 대해 각각 호출한다(둘 중 하나가
없으면 - `usrQuotaInum`/`grpQuotaInum` 필드가 0이면 - 그 호출만
건너뜀, 이미 있는 "쿼터 기능 자체가 없는 이미지" 처리와 동일한
패턴).

### 1.3 동시성 - 별도 뮤텍스 + 고정 락 순서

`gQuotaCurspaceMutex`(`AsyncCoroMutex`, `PN-6D2C8836`)를 그룹
쿼터에도 그대로 재사용할지, 별도로 `gGroupQuotaCurspaceMutex`를
새로 둘지가 결정이 필요한 지점이다. **별도 뮤텍스를 권장**한다 -
사용자 쿼터 파일과 그룹 쿼터 파일은 서로 다른 물리 블록에 있는
완전히 별개 자원이라, 같은 락 하나로 묶으면 서로 무관한 usr/grp
갱신까지 불필요하게 직렬화된다. 락 순서는 **"usr 먼저, grp
나중"으로 고정**해 데드락을 구조적으로 차단한다 -
`InodeTableLockTable`(`PN-CA92C4A7`)이 이미 확립한 "부모 먼저,
자신 나중" 고정 순서 관례와 같은 패턴.

## 2. 설계 B - 트리 삽입(신규 uid/gid)

### 2.1 두 케이스로 나뉜다

- **(b-1) 대상 리프에 빈 슬롯(freeEntry)이 있는 경우** - 상대적으로
  단순하다. `PN-D168A778` 3단계가 이미 실측으로 확인해 둔 "freeEntry
  재사용 정책"(서로 다른 인덱스 경로가 같은 리프 블록을 공유할 수
  있음)을 그대로 따라, 그 빈 슬롯에 새 `QuotaV2DiskDqblk`(curspace=0,
  이번 델타로 초기화)를 써넣고 리프 헤더의 엔트리 카운트를 갱신한다.
- **(b-2) 리프가 가득 찬 경우** - 리프 분할이 필요하다.

### 2.2 (b-2)는 이 설계에서 완전히 확정하지 않는다 (CLAUDE.md 규칙4)

`PN-9AA8B1EF`(ext4 htree 디렉터리 리프 분할)이 만든 "half_md4 해시
+ dx_root 파싱" 절차는 **디렉터리 htree 전용 알고리즘**이라 quota
qtree(리눅스 `fs/quota/quotaio_v2.h` 계열의 radix-tree, 완전히
다른 자료구조 - 해시 기반이 아니라 uid/gid 값 자체를 키로 쓰는
고정 깊이 4단계 트리)에는 그대로 재사용할 수 없다.

quota qtree는 트리 깊이가 고정(`kQtreeDepth=4`)이라는 점이 htree와
다르다 - 리눅스 원본이 실제로 "리프를 분할"하는지, 아니면 "가득 찬
리프를 감지하면 그냥 새 블록을 할당해 다른 방식으로 연결"하는지는
**이 설계 문서 작성 시점에는 확인하지 않았다**. **착수 세션이
로컬 리눅스 커널 소스(`fs/quota/quotaio_v2.c`의 `qtree_write_dquot`/
`do_insert_tree` 계열 함수, `RM-23F4B687` §4 근거 - 실측 없이
알고리즘을 지어내지 않음)를 먼저 대조해 실제 절차를 확정한 뒤
구현할 것**을 제안한다 - 이 SP는 (b-1)만 확정된 설계로 명시하고,
(b-2)는 "착수 세션이 소스 대조 후 확정할 열린 항목"으로 남긴다.

## 3. 설계 C - curinodes(inode 개수 쿼터)

### 3.1 curspace의 정확한 대칭 - 새 인프라 불필요

`QuotaV2DiskDqblk`는 `curspace`(공간)와 나란히 `curinodes`(개수)
필드를 이미 갖고 있다(온디스크 포맷 자체가 둘을 같은 레코드에
담음). §2/§3(증분/감소)가 만든 curspace 코드를 그대로 복제해 필드만
`curinodes`로, 델타를 "블록 개수"가 아니라 "inode 1개"로 바꾸면
된다 - 새로운 자료구조나 순회 로직이 필요 없다.

### 3.2 증분/감소 지점

- **증분**: 새 inode가 실제로 할당되는 지점 - 지금 이 커널에서
  이미 존재하는 유일한 지점은 `Mkdir`(새 디렉터리 inode 할당,
  `ext4_driver.cpp` 약 2290행 인근). 향후 일반 파일 `Create`/
  `Symlink` syscall이 생기면 그 지점에도 같은 패턴을 추가.
- **감소**: inode가 실제로 해제되는 지점 - `Unlink`/`Rmdir`.
- **하드리밋**: §1의 curspace/`bhardlimit` 체크를 curinodes/
  `ihardlimit`로 그대로 복제(같은 리프 레코드에 이미 존재하는
  필드).

### 3.3 소유자 판정

curspace의 3단계가 이미 확립한 원칙("삭제를 요청한 프로세스의 uid가
아니라 **그 파일 소유자**의 uid로 회계")을 그대로 따른다 - inode
소유자 판정 로직을 재사용.

## 4. 우선순위 권장

**curinodes(C) > 그룹 쿼터(A) > 트리 삽입(B)**:
- C는 이미 검증된 코드의 단순 필드 교체 복제라 리스크가 가장 낮다.
- A는 함수 리팩터 + 새 뮤텍스 하나만 필요해 중간 리스크.
- B는 (b-1)은 낮은 리스크지만 (b-2)가 실제 리눅스 소스 대조부터
  시작해야 하는 열린 설계라 가장 나중에 착수할 것을 권장.
