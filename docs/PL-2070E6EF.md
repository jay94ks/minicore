# 실행 계획: MSI/MSI-X 인터럽트 지원

설계자 지시(DS-D4E5C451)로 등록. **이 프로젝트엔 아직 PCI/PCIe 설정
공간 접근 코드 자체가 전혀 없다** - 이게 실질적인 선행 조건이자
이 계획의 0단계다.

## 선행 조건 (이 계획에 포함해서 진행)

- 최소 PCI Configuration Space 접근(레거시 메커니즘 #1: 포트
  0xCF8/0xCFC, 또는 MCFG 기반 MMCONFIG) - 아직 없음.
- IOAPIC 계획(핀 기반 라우팅과의 차이를 이해하는 데 참고, 직접 의존은
  아님).

## 단계

1. **PCI 설정 공간 최소 구현**: `minicore/kernel/pci.h/.cpp` 신설.
   포트 0xCF8(CONFIG_ADDRESS)/0xCFC(CONFIG_DATA)로 bus/device/
   function/register 지정해 32비트 단위 읽기/쓰기. (MMCONFIG는 ACPI
   MCFG 테이블 파싱이 추가로 필요해 v1은 레거시 메커니즘만.)
2. **PCI 버스 열거**: bus 0부터 훑어 vendor ID(0xFFFF면 없음)로 존재
   여부 판정, 필요하면 secondary bus를 재귀 탐색(bridge). 발견한
   장치를 로그로 남긴다(vendor/device id, class code).
3. **MSI capability 탐색**: 각 장치의 Capabilities List(status
   레지스터 bit4 확인 후 capability pointer 따라가기)에서 MSI
   (capability id 0x05) 또는 MSI-X(0x11) 항목을 찾는다.
4. **MSI 메시지 프로그래밍**: Message Address = `0xFEE00000 |
   (destApicId << 12)`, Message Data = 벡터 번호(하위 8비트) - 이
   값을 해당 capability의 주소/데이터 레지스터에 쓰고 Enable 비트를
   켠다. (MSI-X는 별도 BAR의 테이블 엔트리에 씀 - 구조가 달라 MSI를
   먼저 끝내고 그다음 확장.)
5. **벡터/핸들러 등록**: IOAPIC 계획에서 만들 "벡터 -> 콜백" 테이블을
   그대로 재사용 - MSI는 IOAPIC 리다이렉션 테이블 슬롯을 안 쓰므로
   더 많은 장치를 붙일 수 있다는 이점이 실제로 드러나는 지점.
6. **검증**: QEMU에 MSI를 지원하는 가상 장치(예: virtio-net,
   `-device virtio-net-pci`)를 붙여 그 장치의 MSI가 실제로 우리
   벡터로 들어오는지 확인.

## 미결 사항

- MMCONFIG(MCFG 기반)까지 지금 할지, 레거시 0xCF8만으로 충분한지
  - 레거시 메커니즘은 256바이트 설정 공간만 접근 가능(PCIe 확장
    설정 공간 4KB는 MMCONFIG 필요) - MSI 자체엔 지장 없지만 다른
    PCIe 기능을 나중에 쓸 때 다시 논의 필요.
