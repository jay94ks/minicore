# 커널용 lock-free 공유/약한 포인터 템플릿 (`SharedPtr<T>`/`WeakPtr<T>`) — 설계 제안

설계자 메시지(2026-09-16): "lock-free 기반으로 커널용 공유 포인터
템플릿들을 설계해봐."

**이건 완전히 새로운 개념이 아니다** - `AsyncTaskWeakRef`(async_task.h/
.cpp, PN-D01B7D07, SP-F682B889 §3.7)가 이미 정확히 이 패턴을
AsyncTask 전용으로 한 번 구현해 뒀다(그때도 설계자 지시가 "lock-free
기반으로 약한 참조를 구현해"로 문구까지 거의 동일했다, 실측 확인). 이
문서는 **그 검증된 패턴을 임의 타입 `T`에 쓸 수 있는 범용 템플릿으로
일반화**한다 - `EventTopicRegistry`가 SP-71DA77B3의 검증된 구독자
슬롯 패턴을 일반화했던 것과 같은 종류의 작업이다.

## 1. 기존 패턴 실측(`AsyncTaskWeakRef`) - 이 설계의 출발점

```cpp
// async_task.cpp의 실제 코드(발췌, AsyncTask 전용)
class AsyncTaskWeakRef {
public:
    void init(AsyncTask* target) {
        _target.store(target);
        _refCount.store(2);  // AsyncTask 쪽 몫 1 + 타이머 콜백 쪽 몫 1
    }
    AsyncTask* lock() const { return _target.load(); }
    void invalidate() { _target.store(nullptr); }
    void release() {
        if (_refCount.fetchSub(1) == 1) {
            GenericSlabAllocator::free(this, sizeof(AsyncTaskWeakRef));
        }
    }
private:
    AtomicPtr<AsyncTask> _target;
    AtomicU32 _refCount;
};
```

핵심 통찰(기존 헤더 주석이 이미 정리해 둔 것, 이 문서가 그대로
계승): **대상(`T`)의 수명과 컨트롤 블록 자체의 수명을 분리**한다 -
대상이 죽어도(`invalidate()`) 컨트롤 블록은 아직 참여자가 남아 있으면
살아있고, 컨트롤 블록의 참조 카운트가 0이 될 때만 블록 자신이
반납된다. 두 원자 변수(`AtomicPtr<T>`/`AtomicU32`, 둘 다 이미
`libkenv/spinlock.h`에 존재) 만으로 락 없이 두 가지 질문("대상이
아직 살아있는가", "이 블록을 아직 누가 쓰고 있는가")에 안전하게
답한다 - 협조적 스케줄링(리액터 idle 경로/타이머 콜백이 서로 겹치지
않음, 인터럽트 컨텍스트 제외)이 이 안전성의 전제라는 점도 그대로
계승한다(§5).

## 2. 일반화 - `ControlBlock<T>` + `SharedPtr<T>`/`WeakPtr<T>`

`AsyncTaskWeakRef`는 "강한 참조"(대상을 살려 두는 쪽) 개념이 없다 -
AsyncTask 자신의 수명은 리액터가 별도로 관리하고, weakRef는 오직
"이미 죽었는지 아닌지 안전하게 물어보는" 용도였다. 범용 템플릿은
표준 `shared_ptr`/`weak_ptr` 관례대로 **강한 참조(`SharedPtr<T>`,
대상을 살아있게 유지)**와 **약한 참조(`WeakPtr<T>`, 대상 수명에
영향 없음)**를 함께 지원한다 - `strongCount`가 0이 되면 대상이
파괴되고, `weakCount`(강한 참조가 하나라도 있으면 암묵적으로 +1,
표준 `shared_ptr`와 동일 관례)가 0이 되면 컨트롤 블록 자신이
반납된다.

```cpp
// minicore/libs/libkenv/shared_ptr.h (신규)
namespace kernel {

template <typename T>
class ControlBlock {
public:
    // AsyncTaskWeakRef::init()과 동일한 관례 - GenericSlabAllocator가
    // 준 raw 메모리 위에 앉힌 뒤 명시적으로 초기화(placement new 안 씀).
    void init(T* target) {
        _target.store(target);
        _strongCount.store(1);  // 최초 SharedPtr 생성자 몫
        _weakCount.store(1);    // 강한 참조가 하나라도 있는 동안의 암묵적 몫(표준 shared_ptr 관례)
    }

    // WeakPtr::lock()이 쓴다 - "0에서 다시 살아나지 않게" CAS 루프로
    // strongCount를 원자적으로 증가(0이면 실패, 이미 파괴된 대상을
    // 되살리지 않음 - AtomicU32::fetchAdd 단독으로는 이 보장이 안 됨).
    bool tryAddStrongRef() {
        uint32_t cur = _strongCount.load();
        while (cur != 0) {
            if (_strongCount.compareExchange(cur, cur + 1)) {
                return true;
            }
            // compareExchange 실패 시 cur가 최신값으로 갱신됨(관례,
            // spinlock.h의 기존 compareExchange 시그니처 그대로) - 재시도.
        }
        return false;  // 이미 0 - 대상이 파괴됨, 되살릴 수 없음
    }

    T* target() const { return _target.load(); }

    // SharedPtr 소멸/재대입 시 호출 - 소멸자는 T가 소거된 이 템플릿
    // 안에서 직접 부를 수 없으므로(비침습적 설계, T가 완전한 타입일
    // 필요는 SharedPtr<T> 쪽에만 있음) 함수 포인터로 받는다.
    void releaseStrong(void (*destroyFn)(T*)) {
        if (_strongCount.fetchSub(1) == 1) {
            T* t = _target.load();
            if (t) {
                destroyFn(t);
            }
            _target.store(nullptr);
            releaseWeak();  // 강한 참조 전부 사라짐 - 암묵적 weak 1개도 해제
        }
    }

    void releaseWeak() {
        if (_weakCount.fetchSub(1) == 1) {
            GenericSlabAllocator::free(this, sizeof(ControlBlock<T>));
        }
    }

    void addWeakRef() { _weakCount.fetchAdd(1); }

    // SharedPtr 복사 생성자 전용 - 호출자가 이미 강한 참조 1개를 쥔
    // 채로 부르므로(카운트가 0일 수 없음) tryAddStrongRef()의 CAS
    // 루프 없이 단순 fetchAdd로 충분하다.
    void addStrongRefUnchecked() { _strongCount.fetchAdd(1); }

private:
    AtomicPtr<T> _target;
    AtomicU32 _strongCount;
    AtomicU32 _weakCount;
};

template <typename T>
class WeakPtr;

// RAII 강한 참조 - 대상을 살아있게 유지한다.
template <typename T>
class SharedPtr {
public:
    SharedPtr() = default;
    ~SharedPtr() { reset(); }

    SharedPtr(const SharedPtr& other) : _block(other._block) {
        if (_block) _block->addStrongRefUnchecked();  // 이미 살아있는 SharedPtr에서 복사 - tryAddStrongRef의 CAS 불필요, 단순 fetchAdd로 충분(호출자가 이미 강한 참조 1개를 쥐고 있으므로 0에서 시작할 수 없음)
    }
    SharedPtr(SharedPtr&& other) noexcept : _block(other._block) { other._block = nullptr; }
    SharedPtr& operator=(const SharedPtr&) /* 위 복사 생성자와 동일 패턴, 생략 */;
    SharedPtr& operator=(SharedPtr&&) noexcept /* 이동, 생략 */;

    T* get() const { return _block ? _block->target() : nullptr; }
    T* operator->() const { return get(); }
    T& operator*() const { return *get(); }
    explicit operator bool() const { return get() != nullptr; }

    void reset() {
        if (_block) {
            _block->releaseStrong(&kDestroyAndFree<T>);
            _block = nullptr;
        }
    }

private:
    friend class WeakPtr<T>;
    explicit SharedPtr(ControlBlock<T>* block) : _block(block) {}
    ControlBlock<T>* _block = nullptr;
};

// 약한 참조 - AsyncTaskWeakRef와 동일한 역할이지만 임의 T에 대해.
template <typename T>
class WeakPtr {
public:
    WeakPtr() = default;
    explicit WeakPtr(const SharedPtr<T>& shared) : _block(shared._block) {
        if (_block) _block->addWeakRef();
    }
    ~WeakPtr() { if (_block) _block->releaseWeak(); }

    // AsyncTaskWeakRef::lock()과 동일한 역할이지만, "대상을 살려
    // 두는" SharedPtr을 반환한다(표준 weak_ptr::lock() 관례) - 대상이
    // 이미 파괴됐으면(strongCount==0) 빈 SharedPtr.
    SharedPtr<T> lock() const {
        if (_block && _block->tryAddStrongRef()) {
            return SharedPtr<T>(_block);
        }
        return SharedPtr<T>();
    }

private:
    ControlBlock<T>* _block = nullptr;
};

// GenericSlabAllocator로 대상 T와 ControlBlock<T>를 각각 따로 할당
// (AsyncTaskWeakRef와 동일하게 raw slab 메모리 위에 앉힘, placement
// new 없이 명시적 초기화 - T의 생성자를 어떻게 호출할지는 T가 이미
// 이 프로젝트 관례대로 init()류 명시적 초기화 메서드를 갖는다는
// 전제. 인자 전달형 kMakeShared(Args&&...)는 T가 진짜 생성자를 쓰는
// 경우를 위한 옵션 - 착수 시 이 프로젝트에서 실제로 어느 쪽이
// 필요한지 첫 소비자 기준으로 확정).
template <typename T>
SharedPtr<T> kMakeShared(T* preConstructed) {
    void* mem = GenericSlabAllocator::alloc(sizeof(ControlBlock<T>));
    if (!mem) return SharedPtr<T>();  // 할당 실패 - 빈 SharedPtr(예외 없음, 이 프로젝트 관례)
    auto* block = reinterpret_cast<ControlBlock<T>*>(mem);
    block->init(preConstructed);
    return SharedPtr<T>(block);  // private 생성자, friend 또는 팩토리 함수로만 생성 가능
}

}  // namespace kernel
```

## 3. `AsyncTaskWeakRef`와의 관계 - 당장 교체하지 않는다

`AsyncTaskWeakRef`는 **강한 참조 개념이 없는** 순수 약한 참조
전용(§1) - 이 문서의 `WeakPtr<T>`가 정확히 그 상위 호환이지만,
`AsyncTask`가 애초에 `SharedPtr<AsyncTask>`로 관리되는 대상이
아니다(리액터가 직접 스택풀/슬랩으로 수명 관리, §1의 "생성 시 2로
시작" 관례 자체가 `SharedPtr` 없이 참여자 두 곳이 수동으로 카운트를
나눠 가진 특수 사례). **`AsyncTaskWeakRef`를 `WeakPtr<AsyncTask>`로
교체하는 건 이 문서의 범위가 아니다** - 동작 중인 코드(PN-D01B7D07
구현 완료)를 검증되지 않은 리팩터로 건드릴 이유가 없다(RM-23F4B687
§4) - 향후 실제 필요가 생기면(예: 성능/코드 중복 문제가 실측으로
드러나면) 별도로 재검토한다.

## 4. 이 템플릿의 실사용처 후보 (참고, 이 계획의 착수 조건은 아님)

- SP-9A6D579F(프로세스 디버깅) §3.1의 `DebugSession`이 `debuggerProcess`/
  `debuggeeProcess`를 `ProcessId`(정수)가 아니라 `WeakPtr<Process>`로
  들면, 디버거/디버기 중 하나가 먼저 죽어도 안전하게 감지 가능 -
  착수 시 `ProcessId` 방식과 비교해 재검토할 만하다.
- `DebugSession::breakpoints`가 참조하는 대상 스레드도 동일.
- 향후 프로세스 트리(PN-543C0CE9/SP-6BEAE0C1)의 부모→자식 목록이
  자식이 먼저 죽는 경우를 다뤄야 한다면 `WeakPtr<Process>` 목록이
  자연스러운 후보.

이 문서는 이 후보들을 **강제하지 않는다** - 템플릿 자체의 설계만
확정하고, 각 소비자가 실제로 쓸지는 그 소비자 쪽 문서/계획에서
개별적으로 판단한다(CLAUDE.md 규칙 4 - 임의로 다른 문서를 이
템플릿을 쓰도록 고치지 않는다).

## 5. 동시성 계약 (기존 `AsyncTaskWeakRef` 주석의 일반화)

- `tryAddStrongRef()`/`releaseStrong()`/`releaseWeak()`은 CAS/원자
  연산만으로 구현되어 **스핀락이 전혀 필요 없다**(설계자 지시
  "lock-free 기반"의 핵심 - `AsyncTaskWeakRef`가 이미 증명한 성질을
  그대로 계승).
- 다만 `T` 자신의 소멸/정리 로직(`kDestroyAndFree<T>`)이 스레드
  안전한지는 **이 템플릿의 책임이 아니다** - `strongCount`가 정확히
  한 번만 0에 도달함을 원자적으로 보장하므로 소멸자가 정확히 한
  번만 호출됨은 보장되지만, 그 소멸자 본문 자체가 락이 필요한
  작업을 하면 그건 `T`가 알아서 할 일이다.
- `AsyncTaskWeakRef`와 달리 이 템플릿은 **범용**(어느 컨텍스트에서
  호출될지 모름)이므로 "협조적 스케줄링이라 진짜 동시 실행 경쟁이
  없다"는 그 문서의 전제를 그대로 가정하지 않는다 - 위 원자
  연산만으로 진짜 다중 코어 동시 접근에도 안전하다(그게 "lock-free"
  요구의 취지로 해석했다).

## 6. 범위 밖 (v1)

- `AtomicPtr<T>` 자체의 ABA 문제 완화(태그 포인터 등) - 이 프로젝트
  전반의 `AtomicPtr<T>` 사용처(예: TLB 샷다운 `AtomicU32::fetchOr`
  기반 pending mask, `AsyncTask::next` 침습적 리스트)가 지금까지
  ABA를 겪을 만한 재사용 패턴(같은 주소가 빠르게 재할당되는 free-list
  등)을 쓰지 않는다 - 필요해지면 별도 검토.
- 배열/`enable_shared_from_this`류 편의 기능.
- 커스텀 삭제자(deleter) 파라미터화 - v1은 `GenericSlabAllocator::free`
  고정.

## 7. 착수 조건

없음 - `AtomicU32`/`AtomicPtr<T>`(둘 다 이미 구현 완료,
libkenv/spinlock.h)/`GenericSlabAllocator`(이미 구현 완료)만으로
바로 착수 가능. `AsyncTaskWeakRef`라는 실제로 동작 검증된 선례가
있어 설계 위험도 낮다.
