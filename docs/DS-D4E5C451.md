# Minicore 초기 설계 결정 확정 (빌드/부팅/커널서비스/라이선스)

DC-48565C0B / DC-427BB6B2 / DC-5AB13FFC에서 제기된 질의(QU-*)에 대해
설계자가 확정한 결정과 근거를 기록한다. 코딩 컨벤션 세부(헤더 가드,
예외/RTTI, 네이밍)는 RM-23F4B687에 반영했으므로 여기서는 다루지 않는다.

## 빌드 시스템 / 툴체인 / CI (DC-48565C0B)

- **빌드 시스템: CMake** (QU-B14AEB6E).
- **컴파일러: WSL 환경의 clang** — 설치 여부를 먼저 확인하고 그것을
  쓴다(QU-BC00E475).
- **CI: 처음엔 로컬 수동 검증만** — 초기 개발 속도 우선, 자동화는
  나중 단계로 미룬다(QU-C7B4B29F).
- **QEMU 부팅 스모크 테스트는 지금부터 스크립트로 자동화**한다 —
  CI 자체는 아직이지만, 로컬에서도 시리얼 로그 확인을 스크립트화해
  QA-26450C3E의 "부팅" 체크리스트를 반복 검증할 수 있게 한다
  (QU-A2D0CDE0).

## 부트 경로 착수 순서 및 부트로더 방식 (DC-427BB6B2)

- **첫 구현 대상: multiboot2**(QU-813EAEE7). BIOS/PVH/EFI는 이후
  순서대로 추가.
- **부트로더는 직접 구현하지 않고 기존 부트로더를 체인로더로 활용**
  한다(QU-42F20587) — 초기 구현 속도 우선.
- **EFI(UEFI)도 자체 .efi를 작성하지 않고 기존 UEFI 부트로더에
  의존**한다(QU-D579D739) — 위 결정과 일관된 선택.

## 커널 서비스 내부 알고리즘 (DC-5AB13FFC)

- **메모리 할당자**: 관리자(매니저) 본체는 커널에 구현하고, `libkmm`은
  재사용 가능한 알고리즘/자료구조만 제공하는 라이브러리로 둔다. 할당
  알고리즘은 **페이지 단위 + buddy allocator**를 기본으로 하고
  **NUMA**를 고려해 설계한다(QU-F34FF02C).
- **스케줄러**: 코어별 **개별 큐 구조** + **CPU affinity** +
  **CAS(compare-and-swap) 기반 동기화**. 코어간 로드밸런싱은
  **Push/Pull 방식**을 사용한다(QU-C3EC2C63).
- **IPC 메시지 포맷**: **raw binary**(별도 직렬화 포맷 없음)
  (QU-AB52C251).
- **프로세스간 "공개 인터페이스" registry / 제어 채널 프로토콜**:
  지금 확정하지 않고 **구현하면서 추가 설계로 계속 보강**한다
  (QU-6EEFDBEE) — 아직 열린 설계 영역이다.
- **procfs 스키마**: 위와 동일하게 **구현하면서 추가 설계로 계속
  보강**한다(QU-4B14289E) — 아직 열린 설계 영역이다.
- **devmgr 드라이버 모델**: devmgr은 "커널 서비스"로 분류되지만
  **실제로는 유저랜드에서 동작**한다. 커널은 devmgr에게 **필수적인
  IO 처리만 위임**하고 나머지 드라이버 로직은 유저랜드 devmgr이
  담당한다(QU-462F6D89).
