# 실행 계획: HPET 지원

설계자 지시(DS-D4E5C451)로 등록. **역할 확정(QU-8E14D3D9,
2026-09-14): HPET을 작업 스케줄러의 기본(default) 시간원으로 쓰고,
LAPIC 타이머는 fallback으로 유지한다.** PIT는 최초 LAPIC 타이머
보정에만 계속 쓰고(현재 그대로), HPET/LAPIC 두 타이머 경로는 서로
대체가 아니라 "평소엔 HPET, HPET가 없거나 실패하면 LAPIC 타이머"
관계로 유지한다.

## 선행 조건

- 없음(ACPI 파싱 인프라는 이미 있음 - acpi.cpp의 kFindTable을 그대로
  재사용해 "HPET" 시그니처 테이블을 찾으면 됨).

## 단계

1. **ACPI HPET 테이블 파싱**: acpi.cpp에 `kFindTable<...>(sdtPhys,
   "HPET")` 호출 추가 - HPET 테이블 구조체(하드웨어 revision, 비교기
   개수, MMIO 기본 주소 등)를 정의하고 파싱. `Acpi::hpetAddress()`
   등으로 공개.
2. **HPET MMIO 매핑**: LAPIC/IOAPIC과 동일 패턴(PAGE_CACHE_DISABLE).
3. **메인 카운터 읽기/비교기 설정**: General Capabilities 레지스터에서
   카운터 주기(femtoseconds 단위)를 읽어 실제 Hz로 환산. 스케줄러
   틱을 HPET 비교기 인터럽트로 받을 수 있게 비교기(최소 1개) 설정 -
   IOAPIC 계획의 "벡터 -> 콜백" 테이블에 등록.
4. **LAPIC 타이머는 fallback으로 유지**: `Timer::init()`이 HPET 테이블
   존재 여부로 분기 - **있으면 HPET 비교기를 스케줄러 틱 소스로
   쓰고, 없으면 지금처럼 PIT 보정 LAPIC 타이머를 쓴다.** LAPIC
   타이머 보정/등록 코드 자체는 그대로 남겨 둔다(fallback이니 삭제
   금지).
5. **SMP와의 관계(스케줄러 설계 시 재확인 필요)**: HPET은 코어별이
   아니라 시스템에 하나뿐인 전역 카운터/비교기라, 코어마다 독립적인
   틱을 주는 LAPIC 타이머와 근본적으로 다르다 - "스케줄러 기본값이
   HPET"이라는 결정이 멀티코어 환경에서 정확히 어떻게 동작하는지
   (예: HPET 인터럽트 하나를 BSP가 받아 나머지 코어에 IPI로 전파하는
   방식 등)는 SMP AP 기동(PL-65C20380) 이후 스케줄러를 실제로 설계할
   때 다시 짚어야 한다 - 지금 단계에서 미리 확정하지 않는다.
6. **검증**: HPET 비교기 인터럽트가 실제로 반복 발생하는지(타이머
   마일스톤 때와 같은 방식의 자체 테스트), 그리고 HPET 테이블을 없는
   것처럼 강제했을 때 LAPIC fallback 경로가 정상 동작하는지 둘 다
   확인.

## 미결 사항

- 없음(핵심 정책은 확정) - 다만 위 5번(SMP에서의 정확한 동작 방식)은
  스케줄러 설계 시점에 별도로 구체화한다.
