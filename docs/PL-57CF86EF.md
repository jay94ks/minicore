# 실행 계획: 4K 페이지의 2M 페이지 병합/분할

**[설계 확정, 구현 대기, 2026-09-14]** DC-474EE823/QU-87D0CE15 답변으로
설계가 확정됐다. 아직 구현은 시작하지 않았다 - 이 문서는 착수 시
그대로 따를 계획을 남겨 둔다.

## 배경

DC-474EE823 참고 - SP-8B6B8D25 §2 항목8("페이지 병합")과
QA-26450C3E("4K 페이지가 조건에 따라 2M 페이지로 병합된다")가
남겨 둔 미정 사항을 요구분석으로 등록했고, 설계자가 아래처럼
전부 확정해 줬다(QU-87D0CE15, 2026-09-14).

## 확정된 설계

1. **병합 경로 세 가지 모두 구현**:
   - (a) **매핑 시점 즉시 대형 페이지**: 요청받은 범위가 2M 정렬 +
     512개 연속 물리 프레임 조건을 만족하면 그 자리에서 바로 PD에
     PS 비트로 매핑(4K 엔트리를 아예 안 거침).
   - (b) **임계치 기반 사후 컴팩션**: 정기(타이머) 컴팩션이 아니라,
     "4K 페이지가 너무 많이 맵핑돼서 맵핑 테이블이 커지는 시점"에
     트리거한다 - 구체적 임계치(예: 특정 PT/노드 안의 4K 매핑
     개수, 또는 전체 4K 매핑 총량)는 착수 시 계측해서 정한다.
   - (c) **명시적 API 호출**: 호출부가 직접 "이 범위를 병합해라"라고
     요청할 수 있는 공개 함수도 제공한다.
2. **분할(split)도 구현**: 2M로 병합된 영역 중 일부(4K 단위)만
   해제/재매핑해야 하는 상황이 오면, 그 시점에 2M 엔트리를 다시
   512개 4K 엔트리로 되돌린 뒤 필요한 부분만 처리한다.
3. **지금 시점에 구현·검증까지 완료**: 당장 뚜렷한 소비자가 없어도
   미루지 않는다 - PCI MMCONFIG(이미 연속 4K 256개, 가장 쉬운 실측
   대상)를 1차 검증 사례로 쓸 수 있다.
4. **병합 조건(불변 조건)**: 2M 정렬 구간 안의 512개 PT 엔트리가
   - 전부 present이고
   - 물리주소가 연속(엔트리 i의 물리주소 == base + i*4KiB)이고
   - PAGE_WRITABLE/PAGE_USER/PAGE_CACHE_DISABLE 등 플래그가 전부
     동일할 때만 병합 가능. 하나라도 다르면 그 2M 구간은 병합 대상에서
     제외한다(억지 병합/재배치는 아래 5번 경우에만).
5. **버디 할당자와의 관계**: 사후 병합(경로 b)은
   - 명시적 API 호출이 있을 때, 또는
   - 이미 할당된 영역에 페이지를 추가로 할당할 때(예: 지연 매핑
     구역이 점점 채워지는 경우)
   에만 고려한다. 이때 물리 연속성을 검사해서, 4번 조건을 만족하면
   그대로 병합하고, 만족하지 않으면(연속 아님/플래그 불일치) **페이지를
   옮겨서라도(재배치, relocate)** 2M 정렬을 맞춰 병합을 수행한다 -
   즉 사후 병합은 "이미 흩어진 것 중 우연히 맞는 것만" 합치는 소극적
   방식이 아니라, 필요하면 프레임을 재배치까지 하는 적극적 방식이다.

## 구현 시 확인해야 할 것 (착수 시 이어서 조사)

- `PageFrameAllocator`는 이미 order 9(2MiB)까지 지원한다(`kMaxOrder
  = 10`) - (a)/재배치(5번) 경로 모두 `allocOrder(9)`를 그대로 재사용할
  수 있을 듯하다.
- (b)의 "임계치" 구체값과 계측 방법(전역 카운터? 노드별? PT별?)은
  설계자가 방향만 정했고 숫자는 안 정해졌다 - 착수 시 실측하며 정한다
  (미정 상태로 남겨도 되는 구현 디테일 - 새 DC 불필요, RM-23F4B687
  §4 취지상 "숫자값" 수준은 구현 중 결정 가능한 범위로 판단).
- 재배치(5번)는 기존 매핑을 언맵하고 새 프레임으로 다시 매핑 +
  이전 프레임 내용을 복사해야 한다 - 이 복사/재매핑 도중 다른 코어가
  같은 가상주소 범위에 접근하면 안 되므로 SMP 환경에서의 동시성
  보호(락 범위)를 설계해야 한다.
- MSI-X/MMCONFIG처럼 캐시비활성(UC) 매핑도 병합 대상에 포함되는지
  재확인(4번 조건상 플래그 일치만 하면 포함되는 게 자연스러움 -
  PAGE_CACHE_DISABLE도 "플래그"의 일부).
