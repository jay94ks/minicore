# Minicore 가상주소 공간 관리자 위임 사항

설계자 지시(2026-09-14, 메시지) - "복잡한 가상 주소 관리자(VMA 트리/
rbtree 등)를 만들지 말고, 단순 증가 방식의 커서(bump allocator) 자리만
인터페이스 형태로 예약해 둘 것. 실제 경계 확정은 이후 mmap 서브시스템
설계 시점으로 위임. 위임 사항도 별도 문서로 기록해둘것." 이 문서는 그
위임 사항 자체를 기록하는 참조 문서다(SP가 아니다 - 설계 제안이 아니라
"지금 안 만들기로 한 것과 그 이유"를 남겨 두는 것이 목적).

## 무엇이 위임됐는가

**전체 가상주소 공간 관리자(mmap/brk 서브시스템)**의 설계와 구현이
후속 과제로 명시적으로 미뤄졌다 - 다음이 전부 이 위임 범위에 포함된다:

- 프로세스별 VMA(Virtual Memory Area) 추적 자료구조(구간 트리/rbtree
  등 범용 구조).
- `mmap`/`munmap`/`brk` 같은 syscall과 그 정책(주소 힌트, 겹침 검사,
  구간 병합/분할, 지연 매핑과의 상호작용).
- 힙(brk) 영역의 정확한 시작/끝 경계 확정(SP-8B6B8D25 §5-A가 이미
  "아직 미정"으로 명시해 둔 부분).

## 왜 지금 안 만드는가

- 지금 당장 가상주소 공간을 실제로 소비하는 수요는 SP-39F18E30(DMA
  버퍼 관리자)의 **"프로세스당 몇 번 안 되는 저빈도 할당"** 뿐이다 -
  범용 VMA 관리자가 해결하는 문제(겹침 검사, 구간 재사용/병합, 대량
  할당/해제 패턴)가 아직 나타나지 않았다.
- 범용 구조(rbtree 등)를 지금 만들면 실제 요구사항(향후 mmap 서브시스템
  이 실제로 어떤 정책을 원하는지)이 나오기도 전에 설계를 고정하게 된다
  - RM-23F4B687 §4가 말하는 "숫자/구조 튜닝은 실측 후" 원칙과 같은
    맥락.

## 임시 조치 (v1 스텁)

SP-39F18E30 §3.2에 정의된 `ProcessVirtualAddressCursor`가 이 위임
기간 동안의 유일한 구현이다 - **인터페이스만 고정하고 내부는 단순
bump(반납/재사용 없음)로 채운다**:

```cpp
class ProcessVirtualAddressCursor {
public:
    uint64_t reserve(uint32_t pageCount);  // 실패 시 0
};
```

호출부(`AllocDmaBuffer` syscall 구현 등)는 이 인터페이스만 알면 되고,
실제 mmap 서브시스템이 설계되면 이 클래스의 **내부 구현만 교체**되면
된다 - 호출부 코드는 바뀌지 않는 것이 이 스텁을 두는 이유다.

## 후속 설계 시점에 반드시 다시 봐야 할 참조 지점

- **SP-8B6B8D25 §5-A** - "힙(brk)/mmap 영역의 정확한 경계는 아직
  미정"이라고 남겨 둔 원 출처.
- **SP-39F18E30 §3.2/§4** - `ProcessVirtualAddressCursor`가 실제로
  쓰이는 유일한 소비자(DMA 버퍼 관리자).
- **`Process::dmaCursor`** - mmap 서브시스템이 생기면 이 필드가 그
  서브시스템의 자료구조로 흡수되거나, 그 서브시스템이 내주는 주소를
  받아 쓰는 방식으로 바뀌어야 한다.

## [종료, 2026-09-14] 이 위임은 끝났다 - SP-2AAD7C8D로 대체됨

설계자가 이 위임을 철회하고 "mmap 서브시스템을 지금 설계하도록 해"
+ "Maple Tree를 구현할 것" + "가상 주소 관리자는 프로세스별 파트와
커널 영역 전용 파트로 나눠야 해"라고 지시했다(2026-09-14, 메시지 3건).
**이 문서가 예상했던 "이 위임이 끝나는 조건"이 실제로 지금 발생한
것** - mmap 서브시스템 설계는 **SP-2AAD7C8D**("mmap 서브시스템 및
Maple Tree 자료구조 — 설계 제안")에서 완료됐고, 이 문서는 그 설계로
대체/흡수되어 더 이상 유효한 위임이 아니다. 이 문서 자체는 "한동안 왜
미뤘었는지"의 역사적 기록으로만 남긴다 - 새로운 설계 판단은 전부
SP-2AAD7C8D를 참고할 것.
