# 실행 계획: IOAPIC 외부 인터럽트 라우팅

**[완료, 2026-09-14]** QA-26450C3E 체크됨. 아래는 완료 기록으로 남긴다.

ACPI MADT로 IOAPIC 주소는 이미 확보했다(Acpi::ioApicAddress()). 지금은
그 주소를 아무데도 안 쓴다 - 실제로 매핑하고 리다이렉션 테이블을
설정해야 키보드 등 핀 기반 레거시 장치 인터럽트가 들어온다.

## 선행 조건

- Acpi::ioApicAddress() (완료)
- Paging::mapPage + PAGE_CACHE_DISABLE (완료 - LAPIC 매핑과 동일한
  패턴 재사용)

## 한 것

1. **IOAPIC MMIO 매핑**: `minicore/kernel/ioapic.h/.cpp` 신설.
   `kIoApicVirtBase = 0xFFFF901000001000UL`(LAPIC의 `kLapicVirtBase`
   바로 다음 4KiB 페이지 - 서로 다른 물리 프레임이라 독립된 가상주소
   필요) + `PAGE_CACHE_DISABLE`로 매핑.
2. **간접 레지스터 접근**: `IOREGSEL`(오프셋 0x00에 레지스터 번호
   기록)+`IOWIN`(오프셋 0x10 읽기/쓰기)의 2단계 방식을 파일 static
   `kReadReg`/`kWriteReg`로 구현.
3. **리다이렉션 테이블 설정**: `IoApic::setRedirection(irq, vector,
   destApicId)` - REDTBL 엔트리(레지스터 0x10+2*irq/+1)에 벡터+목적지
   APIC ID를 쓴다(델리버리 모드/목적지 모드/극성/트리거 모드는 전부
   기본값 0 = Fixed/physical/active-high/edge, 레거시 ISA 인터럽트
   관례와 일치). `mask()`/`unmask()`도 추가.
4. **IDT를 벡터->콜백 표로 일반화**: 기존엔 CPU 예외(0-31)+타이머(32)+
   spurious(0xFF)만 있었다 - `isr.S`에 GAS `.altmacro`+`.rept` 숫자
   루프로 벡터 33-254 스텁 222개를 한꺼번에 찍어내고, 그 주소들을
   `kIsrDynamicStubTable`(rodata 배열)로 노출했다(손으로 222개 extern
   선언하는 대신 이 표 하나만 idt.cpp가 참조). `Idt::registerHandler(
   vector, InterruptHandler)`/`unregisterHandler(vector)`를 공개 API로
   추가 - `kIsrHandler`가 33-254 대역에서 등록된 콜백을 찾아 호출한
   뒤 자동으로 `Lapic::sendEoi()`를 보낸다(장치 핸들러가 EOI를 직접
   안 챙겨도 되게 구조적으로 강제 - 빼먹는 실수 방지). 등록 안 된
   벡터로 인터럽트가 들어오면(라우팅은 했는데 핸들러 등록을 깜빡한
   버그) 조용히 무시하지 않고 `kPanic`으로 멈춘다 - 이때 CPU 예외용
   이름 배열(`kExceptionNames`, 0-31 전용)을 잘못 인덱싱하지 않도록
   벡터 32 이상이면 "Unrouted hardware interrupt"로 별도 표기하게
   `kPanic`도 같이 고쳤다.
5. **검증(실측, 2026-09-14, QEMU 8.2.2)**: 키보드 IRQ1을 벡터 0x21로
   라우팅하고 핸들러를 등록한 뒤, QEMU 모니터의 `sendkey` 명령으로
   실제 키 입력을 주입했다(`-monitor stdio`를 named pipe로 제어해
   부팅 완료 후 지연을 두고 전송). 'a' 입력 → make 0x1E/break 0x9E,
   'b' 입력 → make 0x30/break 0xB0 스캔코드가 핸들러에 정확히
   전달됨을 확인(포트 0x60에서 직접 읽음) - IOAPIC 매핑→REDTBL
   설정→IDT 디스패치→EOI까지 전체 경로가 실제로 동작함을 확인했다.
   검증 후 임시 핸들러/라우팅 호출 코드는 제거했고, `IoApic::init()`
   (MMIO 매핑까지)은 영구 초기화 시퀀스에 남겨 뒀다(HPET 등 후속
   장치가 바로 `setRedirection`을 쓸 수 있게).
   x2APIC(PL-D65F49CC) 모드와 함께 켜도(`-accel kvm -cpu host`) 회귀
   없음을 재확인했다.

## 이번엔 안 한 것 (후속 과제로 남김)

- **ACPI MADT Interrupt Source Override(타입2) 파싱**: 지금은 "IRQ
  번호 == GSI 번호"로 가정한다(`ioapic.h` 주석에 명시). 실제로는
  특정 IRQ(특히 IRQ0)가 다른 GSI로 재배선된 시스템이 있을 수 있다 -
  지금은 재배선이 거의 없는 IRQ1(키보드)만 다뤄서 문제 없었지만,
  PIT(IRQ0) 등을 IOAPIC으로 라우팅해야 할 일이 생기면 이 파싱을
  먼저 `acpi.cpp`에 추가해야 한다.
- **x2APIC 목적지 필드 한계**: REDTBL의 물리 목적지 필드는 8비트라
  x2APIC의 32비트 APIC ID 전체를 못 담는다 - 지금은 BSP 하나뿐이라
  문제 없지만, SMP에서 8비트를 넘는 APIC ID를 가진 코어로 라우팅해야
  하면(대규모 시스템) 재검토 필요(관계도에 기록).

## 미결 사항

- 없음(원래 PL에 있던 "PIT 등 레거시 IRQ도 IOAPIC으로 라우팅할지"는
  LAPIC 타이머/향후 HPET가 이미 PIT를 대체하므로 실질적으로 불필요해
  졌다 - 별도 결정 없이 라우팅하지 않는 쪽으로 자연 확정).
