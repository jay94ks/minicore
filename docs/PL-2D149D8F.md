# 실행 계획: IOAPIC 외부 인터럽트 라우팅

ACPI MADT로 IOAPIC 주소는 이미 확보했다(Acpi::ioApicAddress()). 지금은
그 주소를 아무데도 안 쓴다 - 실제로 매핑하고 리다이렉션 테이블을
설정해야 키보드 등 핀 기반 레거시 장치 인터럽트가 들어온다.

## 선행 조건

- Acpi::ioApicAddress() (완료)
- Paging::mapPage + PAGE_CACHE_DISABLE (완료 - LAPIC 매핑과 동일한
  패턴 재사용)

## 단계

1. **IOAPIC MMIO 매핑**: LAPIC과 같은 방식(전용 가상주소 +
   PAGE_CACHE_DISABLE)으로 매핑. LAPIC과 다른 가상주소 대역을 써서
   겹치지 않게 한다.
2. **간접 레지스터 접근 구현**: IOAPIC은 LAPIC과 달리 IOREGSEL
   (오프셋 0x00에 쓰기로 레지스터 번호 선택) + IOWIN(오프셋 0x10을
   읽거나 써서 실제 값 접근)의 2단계 간접 방식이다 - `IoApic` 클래스에
   `readRegister(u8)`/`writeRegister(u8, u32)` 구현.
3. **리다이렉션 테이블 설정**: 필요한 IRQ(우선 키보드 IRQ1)에 대해
   64비트 리다이렉션 엔트리(REDTBL, 레지스터 0x10+2*irq) 설정 -
   목적지 APIC ID(BSP), 벡터(IDT에 새로 등록할 값, 32~254 중 미사용
   번호), 트리거 모드(엣지)/극성 등.
4. **IDT에 새 벡터 등록 + isr.S에 스텁 추가**: 지금 isr.S는 0-31 +
   32(타이머) + 255(spurious)뿐이다 - IOAPIC이 라우팅할 벡터마다
   `isr_no_err` 매크로로 스텁을 늘린다(범용화 검토: 벡터 33~254를
   전부 미리 찍어내고 idt.cpp에서 핸들러 테이블로 디스패치하는 편이
   매번 손으로 추가하는 것보다 나을 수 있음 - 구현 중 판단).
5. **핸들러 등록 메커니즘**: 지금 kIsrHandler는 하드코딩된 if문으로
   벡터를 분기한다 - 장치별 핸들러를 등록/해제할 수 있는 테이블
   (벡터 -> 콜백)로 일반화해야 IOAPIC/MSI 양쪽이 재사용 가능하다.
6. **검증**: 키보드 IRQ1을 걸어 두고 QEMU에서 키 입력 시 해당 벡터
   ISR이 실제로 불리는지(카운터 증가 등으로) 확인.

## 미결 사항

- 레거시 IRQ(PIT 등)를 IOAPIC으로도 라우팅할지, 아니면 계속 안 쓸지
  (지금은 LAPIC 타이머로 대체했으므로 PIT IRQ0 라우팅은 불필요해
  보이나 확인 필요).
