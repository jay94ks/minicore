# Minicore Syscall 할당표

설계자 지시(2026-09-14, 메시지) - "Syscall ID 할당에 관한 사항도
`Minicore Syscall 할당표`에 정리해둬." `SyscallRegistry`(PL-21344323,
`minicore/kernel/syscall.h`)가 `SyscallEndpointId`(`uint32_t`)를
등록·해석하는 구조다 - 여러 설계 제안 문서가 각자 새 syscall을
"SyscallRegistry에 등록"이라고 언급만 하고 실제 번호는 비워 뒀는데,
이대로 각자 구현 착수하면 번호가 겹칠 수 있다. 이 문서가 **실제
번호를 미리 예약해 두는 단일 출처** 역할을 한다 - RM-7C249618
("Minicore 라이브러리 목록")/RM-C65F7760("Minicore VFS 구조")과
같은 성격의 "현재 상태를 추적하는 현황판" 문서다(설계 문서 자체가
아님).

## [완료, 2026-09-17] Group+Call 2단계 인코딩으로 전면 개편

설계자 지시(2026-09-17, opinion) - 기존의 평평한 0-255 번호 공간을
**그룹(비트 15:8) + 그룹 내 call 번호(비트 7:0)** 2단계로 재편했다
(`SP-E9B44929`, approved, `PN-B522DFEE`로 구현 완료·commit 반영).
비트 31:16은 예약(반드시 0). `SyscallEndpointId` 자체는 여전히
`uint32_t`(와이어 ABI 무변경) - 해석만 바뀐다.

```cpp
// syscall.h
constexpr SyscallEndpointId kMakeSyscallEndpointId(uint8_t group, uint8_t call);
constexpr uint8_t kSyscallGroupOf(SyscallEndpointId id);
constexpr uint8_t kSyscallCallOf(SyscallEndpointId id);
```

**이 문서가 계속 중재하는 것은 그룹 번호(0-255)뿐이다** - 그룹
안의 call 번호는 그 그룹을 소유한 subsystem 설계 문서가 다른
그룹과 조율 없이 0부터 독자적으로 채운다(CLAUDE.md 규칙 10의
"번호부터 예약" 정신은 그룹 단위로 적용). 이 문서는 그래도 "전체
그룹 + 각 그룹의 현재 call 목록"을 한눈에 보여주는 현황판 역할은
유지한다(SP-E9B44929 §5).

**2026-09-16 "빈칸 재사용" 정책은 그룹 재편으로 의미가 사라졌다** -
전역 번호 공간 자체가 없어졌으므로, 폐기된 call 번호를 재사용할지는
이제 그 call이 속했던 그룹의 소유 문서가 독자적으로 판단한다(예:
과거 36/37/46번 자리였던 `UnpublishInterface`/`QueryInterfaces`/
`GetKernelServiceRingBuffer`는 전부 그룹 재편 이전에 이미 폐기된
것들이라 새 그룹표에 자리 자체가 없다 - 해당 그룹 소유 문서가 필요
시 그 그룹 안에서 새 call로 재도입 여부를 판단).

## 기록 규칙

- 새 syscall을 설계 문서에 추가할 때마다, 그 그룹의 call 목록에서
  다음 미사용 call 번호로 행을 추가한다(구현 여부와 무관 - 제안
  단계에서도 번호부터 예약).
- 새 그룹이 필요하면(기존 9개 그룹 중 어디에도 속하지 않는 완전히
  새로운 subsystem) 이 문서의 그룹 배정 표에 다음 미사용 그룹
  번호로 행을 추가한다.
- "상태" 칸: `구현 완료`(실제 `SyscallRegistry::registerHandler` 호출
  코드가 있음) / `번호만 예약`(설계 문서에 구조체는 있으나 아직
  미구현).

## 참고 - `waitForSyscall`/`waitForMultipleSyscall`/`waitAnyForMultipleSyscall`은 여기 없다

`Syscall::wait`/`waitForMultipleSyscall`/`waitAnyForMultipleSyscall`
(SP-04EE2A18, 이미 구현 완료)은 **`SyscallEndpointId`를 갖는 별도
syscall이 아니다** - 이미 제출된(submit된) syscall의 완료를 기다리는
커널 내부 API(AsyncTask 완료 대기)일 뿐이라 이 할당표의 대상이 아니다.
이 표는 오직 `SyscallRegistry::registerHandler`로 등록되는, 고유
`SyscallEndpointId`가 필요한 syscall만 다룬다.
