# Minicore Syscall 할당표

설계자 지시(2026-09-14, 메시지) - "Syscall ID 할당에 관한 사항도
`Minicore Syscall 할당표`에 정리해둬." `SyscallRegistry`(PL-21344323,
`minicore/kernel/syscall.h`)는 `SyscallEndpointId`(`uint32_t`)를 256개
(`kMaxSyscallEndpoints`, v1 상한) 고정 슬롯 배열에 등록하는 구조다 -
여러 설계 제안 문서가 각자 새 syscall을 "SyscallRegistry에 등록"이라고
언급만 하고 실제 번호는 비워 뒀는데, 이대로 각자 구현 착수하면 번호가
겹칠 수 있다. 이 문서가 **실제 번호를 미리 예약해 두는 단일 출처**
역할을 한다 - RM-7C249618("Minicore 라이브러리 목록")/RM-C65F7760
("Minicore VFS 구조")과 같은 성격의 "현재 상태를 추적하는 현황판"
문서다(설계 문서 자체가 아님).

## 기록 규칙

- 새 syscall을 설계 문서에 추가할 때마다, 이 표에 다음 미사용 번호로
  행을 추가한다(구현 여부와 무관 - **제안 단계에서도 번호부터
  예약**해 다른 작업과 충돌하지 않게 한다).
- "상태" 칸: `구현 완료`(실제 `SyscallRegistry::registerHandler` 호출
  코드가 있음) / `번호만 예약`(설계 문서에 구조체는 있으나 아직
  미구현).
- 번호를 재사용하거나 건너뛰지 않는다 - 한 번 예약된 번호는 그
  syscall이 완전히 폐기되지 않는 한 계속 그 자리를 지킨다.

## 참고 - `waitForSyscall`/`waitForMultipleSyscall`/`waitAnyForMultipleSyscall`은 여기 없다

`Syscall::wait`/`waitForMultipleSyscall`/`waitAnyForMultipleSyscall`
(SP-04EE2A18, 이미 구현 완료)은 **`SyscallEndpointId`를 갖는 별도
syscall이 아니다** - 이미 제출된(submit된) syscall의 완료를 기다리는
커널 내부 API(AsyncTask 완료 대기)일 뿐이라 이 할당표의 대상이 아니다.
이 표는 오직 `SyscallRegistry::registerHandler`로 등록되는, 고유
`SyscallEndpointId`가 필요한 syscall만 다룬다.
