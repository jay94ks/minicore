# 실행 계획: 커널 전용 비동기 프레임워크(AsyncTask)

**[설계 확정, 구현 대기, 2026-09-14]** SP-F682B889(2026-09-14 확정)의
`AsyncTask`/`AsyncTaskGroup`/`AsyncTaskWaitGroup`/`AsyncTaskAwaiter`/
`AsyncReactor` 설계를 실제로 구현하기 위한 순서를 남긴다. **착수
전제조건**: Slab 할당자(SP-D7013B26, 아직 검토 대기)가 먼저
확정/구현돼야 한다 - `args`와 `AsyncTask` 전용 스택 할당이 그 위에
얹히기 때문. 스케줄러(PL-2D3184BC)의 즉시 스케줄링 프리미티브
(8-1단계, 이번에 추가)도 선행 조건이다.

## 배경

SP-F682B889/DC-01434F82/QU-F86426D5 참고 - 원래 제안(스택 없는
콜백 체인)이 검토 결과 스택풀(`AsyncTask`, 자체 yield) + 코어당
전용 리액터 Task로 확정됐다.

## 구현 순서 (착수 계획)

0. **[선행조건] Slab 할당자 확정/구현**: SP-D7013B26/DC-4809BB47
   답변 대기 - `libkmm/slab.h/.cpp` 신설, `SlabCache`/
   `GenericSlabAllocator` 구현 및 실측 검증(단일 코어 alloc/free
   반복, 이후 멀티코어 매거진 교환 실측).
1. **[선행조건] 스케줄러 즉시 스케줄링**: PL-2D3184BC 8-1단계 -
   `Scheduler::scheduleImmediate(Task*)` 구현 - 이것도 스케줄러
   본체(4~7단계) 진행과 맞물려야 하므로 스케줄러 큐 구현 이후.
2. **`AsyncTask` 자료구조**: `minicore/kernel/async_task.h/.cpp`
   신설 - `savedRsp`/`stackBase`/상태/`callbackId`/`args`/`next`.
   `Task::init()`과 거의 같은 트램폴린 스택 구성이지만 훨씬 작은
   전용 스택(Slab에서 확보) - `kContextSwitch`/`kTaskStartTrampoline`
   (context_switch.S)을 그대로 재사용할 수 있는지, 아니면 더 작은
   레지스터 셋만 저장하는 경량 버전이 필요한지 구현 시 판단.
3. **`AsyncTask::yield()`**: 현재 AsyncTask 컨텍스트에서 리액터
   컨텍스트로 돌아가는 전용 컨텍스트 전환 경로 - 리액터가 다음
   AsyncTask를 고를 수 있는 지점을 명확히 설계.
4. **`AsyncCallbackRegistry`**: 콜백 등록 표(고정 크기 배열, 벡터
   테이블과 비슷한 패턴 - `Idt::registerHandler`의 벡터->콜백 표
   재사용 경험을 참고).
5. **`AsyncReactor` - 코어당 전용 Task**: `reactorTaskEntry`가
   이 코어의 실행 큐(lock-free, 스케줄러 4단계와 같은 방향)를
   드레인하며 각 AsyncTask를 실행/재개한다. `submitCompletion()`이
   인터럽트 컨텍스트에서 안전하게 호출 가능해야 한다(락 없이 push +
   `Scheduler::scheduleImmediate`로 이 코어 리액터 Task를 깨움).
6. **`AsyncTaskGroup`/`AsyncTaskWaitGroup`/`AsyncTaskAwaiter`**:
   3.3절 API 그대로 구현 - `AsyncTaskWaitGroup::waitAll()`은
   스케줄러의 비공개 block/wake를 쓰고, `AsyncTaskAwaiter::await()`는
   `AsyncTask::yield()` 반복으로 구현.
7. **타임아웃**: HPET 기반 마감 시각을 옵션으로 지원.
8. **검증**: 임시 디버그 콜백(예: HPET 틱을 완료 이벤트로 흉내내는
   가짜 비동기 작업)으로 등록→요청→완료→콜백 실행 전체 경로를
   QEMU에서 실측 - 여러 AsyncTask가 순서대로/중첩(Awaiter)으로
   처리되는지, 리액터가 우선순위 무시 즉시 스케줄링으로 깨어나는지
   확인 후 임시 코드 제거.
