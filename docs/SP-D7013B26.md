# Slab 할당자(libkmm) — 설계 제안

**[확정, 2026-09-14, QU-4F905C08 답변 반영]** 원래 제안(코어당 매거진
1개)은 설계자 검토 결과 **Bonwick 표준 모델대로 코어당 매거진
2개(loaded/previous)**로, 그리고 **선점 방지(PreemptionGuard) 강제
적용**이 필수 수정 사항으로 추가됐다. 수치(매거진 용량/버킷 크기/
슬랩 order/고갈 정책)는 별도 DC 없이 이 답변으로 바로 고정됐다.
아래는 확정된 최종 설계다.

**[구현 완료, 2026-09-14, 계획 PN-DC75D601]** PL-16E2CDA4 참고.

## 1. 배경 / 동기 (기존 유지)

같은 크기 객체(비동기 프레임워크의 `args`, 향후 다른 고정 크기
커널 자료구조)를 반복적으로 할당/해제하는 경로에서 범용 할당자를
매번 거치면 단편화와 오버헤드가 쌓인다. Slab 할당자(Bonwick 1994)
+ 코어별 매거진 확장(Bonwick & Adams 2001, "Magazines and Vmem")을
쓴다 - 설계자가 요구한 "코어 단위 유닛 + 전역 유닛" 구조가 정확히
이 매거진/디포 모델이다.

## 2. 핵심 구조 (확정)

### 2.1 동시성 방어 - 선점 방지 필수 (설계자 지시, 2026-09-14)

**문제**: 코어별 매거진은 "이 코어만 건드린다"는 전제로 락이 없다.
하지만 (a) 매거진 연산 도중 이 실행 흐름이 다른 코어로 마이그레이션
되거나, (b) 인터럽트 핸들러가 같은 매거진 연산에 재진입하면 프리
리스트가 파괴된다.

**해법**: `alloc()`/`free()` 진입 즉시 **선점을 비활성화**(스케줄러의
"선점 비활성화 카운터", PL-2D3184BC 8단계와 동일한 프리미티브 재사용
예정 - `PreemptionGuard` RAII 래퍼)하고, 그 상태로 코어 ID를 얻어
연산이 끝날 때까지 그 코어에 고정되어 있음을 보장한 뒤에만 선점을
복구한다. 이 프리미티브는 스케줄러(PL-2D3184BC)가 먼저 구현해야
Slab 할당자가 쓸 수 있다 - **선행 조건**으로 기록.

```cpp
namespace kernel {

// 진입 시 선점을 비활성화(카운터 증가)하고 소멸 시 복구한다 -
// 이 스코프 안에서는 이 코어의 매거진이 다른 실행 흐름/인터럽트에게
// 방해받지 않는다(PL-2D3184BC 8단계의 선점 금지 구간 프리미티브
// 재사용). 인터럽트 마스킹까지 필요한지는 스케줄러 구현 시 확정.
class PreemptionGuard {
public:
    PreemptionGuard();
    ~PreemptionGuard();
};

}  // namespace kernel
```

### 2.2 2단 구조 - 코어별 더블 매거진(빠른 경로) + 전역 디포

```
[코어 0: loaded+previous] [코어 1: loaded+previous] ... [코어 N: ...]
              \                    |                    /
               \                   |                   /
                [전역 디포: 가득/빈 매거진 목록(lock-free)]
                               |
                        [슬랩 페이지들](PageFrameAllocator order 0)
```

- **더블 매거진(Loaded/Previous)**: 코어마다, 캐시마다 **2개**의
  매거진을 둔다 - `loaded`(현재 쓰는 것)와 `previous`(예비). 단일
  매거진 방식은 alloc/free가 경계값(꽉 참/완전히 빔)에서 번갈아
  일어나면 매번 디포 CAS를 건드려 경합이 폭증한다(thrashing) -
  Bonwick 표준 모델은 이를 막기 위해 2개를 쓴다.
  - **alloc()**: `loaded`에서 pop. `loaded`가 비었으면 `previous`와
    스왑(swap) 먼저 시도 - 스왑 후에도 비었으면(둘 다 빔) 그때만
    디포에서 가득 찬 매거진 하나를 받아 `previous`에 놓고 다시 스왑.
  - **free()**: `loaded`에 push. `loaded`가 가득 찼으면 `previous`와
    스왑 먼저 시도 - 스왑 후에도 가득 차 있으면(둘 다 참) 그때만
    `previous`를 디포에 통째로 넘기고 빈 매거진을 받아 온다.
  - 매거진 용량: **16개로 고정**(설계자 지시) - 포인터 16개(128B)가
    L1D 캐시 2개 라인에 맞아 코어별 유휴 메모리 낭비를 막고 캐시
    친화적이다. 매거진이 총 2개니 캐시 하나당 최대 32개(256B, 4
    캐시라인) 유휴.
- **디포(Depot)**: 캐시마다 전역으로 하나 - 가득/빈 매거진 목록을
  lock-free 스택(`AtomicPtr<T>`, 스케줄러/비동기 프레임워크와 동일한
  CAS 프리미티브)으로 관리.
- **슬랩(Slab)**: **기본 Order 0(4KiB) 전용**(설계자 지시) - 런타임
  외부 단편화 방지 원칙. 512~2048 버킷에 한해 슬랩 페이지 낭비율을
  실측한 뒤 Order 1 적용 여부를 **차후 검토**(지금은 결정 안 함,
  실측 전까지는 Order 0 유지, 계획 PN-DE8C27B1).

### 2.3 API (확정)

```cpp
namespace kernel {

class SlabCache {
public:
    void init(unsigned long objectSize);
    void* alloc();   // 실패 시 nullptr(2.4절 고갈 정책)
    void free(void* ptr);
};

// 요청 크기를 버킷 크기로 올림하는 로직은 반드시 이 함수 하나만
// 거친다(설계자 지시 - "규약 불일치로 인한 슬랩 오분류를 원천
// 차단"). GenericSlabAllocator::free()도 내부에서 이 함수를 다시
// 거쳐 호출부가 잘못된/오래된 크기를 넘겨도 항상 같은 버킷으로
// 되돌아가게 한다.
unsigned long sizeToBucket(unsigned long size);

// 버킷 7단계 고정(설계자 지시): 32/64/128/256/512/1024/2048바이트.
// 32B 미만 요청 금지(빈 객체에 free-list 포인터가 겹쳐 써지므로
// 최소 크기가 필요). 2048B 초과 요청은 슬랩을 거치지 않고
// PageFrameAllocator로 직접 넘긴다(대형 객체를 굳이 버킷화하지
// 않음).
class GenericSlabAllocator {
public:
    static void init();
    static void* alloc(unsigned long size);   // 실패 시 nullptr
    static void free(void* ptr, unsigned long size);  // 내부에서 sizeToBucket 재적용
};

}  // namespace kernel
```

### 2.4 고갈 정책 - 즉시 nullptr, 블로킹 절대 금지(설계자 지시)

디포+`PageFrameAllocator`까지 완전히 고갈되면 `alloc()`은 **즉시
`nullptr`을 반환**한다 - 블로킹/슬립은 절대 하지 않는다. 비동기
런타임(SP-F682B889) 내부에서 메모리 고갈로 슬립에 들어가면
스케줄러 데드락을 유발할 수 있기 때문이다. 할당 실패의 재시도/실패
처리는 **비동기 프레임워크 쪽(SP-F682B889)의 책임**으로 넘긴다 -
콜백을 등록하는 쪽이 실행(exec) 경로뿐 아니라 실패(failure) 경로도
같이 등록해야 한다(SP-F682B889 갱신본 참고).

## 3. 비동기 프레임워크와의 관계 (갱신)

`GenericSlabAllocator::alloc/free`가 `AsyncTask`의 내부 데이터,
그리고 `AsyncTask` 자신의 전용 스택 확보에도 재사용된다. 할당
실패(`nullptr`) 시 처리 책임은 SP-F682B889의 실패 콜백 경로가 진다
(2.4절).

## 4. 선행 조건

- **스케줄러의 선점 비활성화 프리미티브**(PL-2D3184BC 8단계) - Slab
  할당자의 `PreemptionGuard`가 그대로 재사용한다. 스케줄러 본체
  구현이 먼저 어느 정도 진행돼야 착수 가능.

## 5. 이번 답변으로 종결된 항목 (더 이상 미정 아님)

매거진 용량(16 고정), 버킷 크기(32/64/128/256/512/1024/2048 고정),
슬랩 백킹 order(0 고정, 512-2048 버킷의 Order 1은 실측 후 별도 검토
- 새 DC 불필요, 구현 중 계측 데이터로 판단 - 계획 PN-DE8C27B1),
고갈 정책(즉시 nullptr, 비블로킹) - 전부 확정. 512~2048 버킷의
Order 1 적용 여부만 "실측 후 판단"으로 열려 있으나, 이는 숫자
튜닝 수준이라 별도 DC가 필요 없다(RM-23F4B687 §4 취지).
