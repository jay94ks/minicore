# Minicore 라이브러리 목록

새 라이브러리(커널이든 유저랜드든)를 만들 때마다 이 문서에 항목을
추가한다(설계자 지시, 2026-09-14 - CLAUDE.md 규칙에도 명시).

## 커널 측 (minicore/libs/*)

**배치 원칙(2026-09-17, 설계자 의견으로 명시화)**: `minicore/libs/*`는
"커널 코드" 전용이 아니다 - 커널 자신뿐 아니라 **"커널 서비스"**
(devmgr/fs/net/tty/pubreg/authmgr 등, 전부 유저랜드에서 구동되지만
커널이 통제권을 쥔 프로세스, `SP-8B6B8D25` §2-A)의 의존성도 여기
둔다(예: `libkvdb` - authmgr 전용 소비자지만 커널 코드가 아님, 순수
유저랜드 라이브러리). 반대로 일반 최종 사용자 애플리케이션이 쓰는
라이브러리는 `userland/libs/*`(문서 하단)에 둔다 - 구분 기준은
"커널 코드 여부"가 아니라 "커널이 통제하는 서비스 계층의 의존성인가,
아니면 순수 사용자 애플리케이션 계층의 의존성인가"이다.

|---|---|---|---|

## 유저랜드 측 (userland/libs/*, userland/tests/*)

QU-FF3F0CAA 답변(2026-09-14)으로 확정된 디렉터리 체계. 빌드 트리 자체
(`userland/CMakeLists.txt` + `userland/cmake/toolchain-userland-x86_64.cmake`
+ 링커 스크립트, PN-4AD3CBE0 완료)는 준비됐고 검증용
`userland/tests/userlandtest`(순수 툴체인 검증 스텁, 라이브러리 아님)
까지 실제로 빌드됨:

| 이름 | 경로 | 용도 | 상태 |
|---|---|---|---|
| libmc | userland/libs/libmc | 커널 및 "커널 서비스"들의 API를 유저랜드에 노출(MiniCore 라이브러리) | 부분 구현 완료(PN-58269449 스캐폴딩 + PN-71C3D483로 `mc::selfTerminate()`가 실제 `int 0x80` 트랩 발동까지 완성 + PN-BD9AAE2F 3번 항목이 범용 `mc::submit()`/`mc::wait()`(제출/대기 분리 패턴 공용 진입점) 추가, 2026-09-17) - `submit()`/`wait()`는 아직 end-to-end 검증 미완(PN-523B779F 커널 PANIC 버그에 막힘). `pnp.h`(EnumerateDevices 유저랜드 ABI 거울)도 이번에 추가 - 나머지 syscall 래퍼(Channel IPC 등)는 각 엔드포인트가 실제로 필요해지는 시점에 추가 |
| libuserlandtest | userland/tests/libuserlandtest | 테스트용 유저 런타임 라이브러리 - shared/static 양쪽으로 빌드 가능해야 함(동적 라이브러리 지원 검증용) | 예정 |

## 기록 규칙

- 새 라이브러리 디렉터리(`minicore/libs/<name>` 또는
  `userland/{apps,libs,tests}/<name>`)를 실제로 만들 때마다 이 표에
  행을 추가한다 - 계획 단계(아직 코드 없음)는 "상태" 칸에 "예정"으로
  남겨 두고, 실제로 만들어지면 "완료"로 바꾼다.
- "대상" 칸에는 커널 전용/유저 전용/공용(매크로 구분 여부 포함)을
  명시한다.
- 이 문서를 다른 문서에서 인용할 때는 이 문서의 추적 코드를 그대로
  쓴다.
