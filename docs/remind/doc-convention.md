# 문서 관리 규칙 (Doc Convention)

- **작성일**: 2026-09-08
- **출처**: 사용자 지시 (세션 최초 요청)

## 규칙

| 디렉토리 | 용도 | 제약 |
|---|---|---|
| `docs/spec/` | 명세 (무엇을 만들 것인가) | 구현 방법이 아닌 요구사항/인터페이스 계약 |
| `docs/plan/` | 실행 계획 | **실행 전의 계획만** 남긴다 |
| `docs/done/` | 결과 보고 | **실행 완료된 것만** 기록한다 |
| `docs/design/` | 설계/상세 내용 | 구조, 알고리즘, 자료구조, 트레이드오프 |
| `docs/remind/` | 기억 지시 사항 | "기억해" 지시를 받은 내용만 |

## 추가 규칙

1. `docs` 내 **모든** 문서는 `docs/index.md`에 리스팅되어야 한다 —
   단, 하위 디렉토리가 자체 색인(`<하위디렉토리>/index.md`)을 가지면
   최상위 `docs/index.md`는 그 색인 파일 하나만 가리켜도 된다(2번째
   규칙 참고). `docs/design/`이 그 예다.
2. 문서 파일명은 `kebab-case.md`를 사용한다.
3. 계획(`plan`)이 실행되면 결과를 `done`에 기록한다. `plan` 문서는 실행 전 상태 그대로 남긴다.
4. 문서가 많아진 카테고리(예: 설계 결정 ADR)는 하나의 거대한 파일
   대신 **주제별로 분리**하고, 그 디렉토리 안에 `index.md`를 두어
   무엇이 어디 있는지 안내한다 (`docs/design/index.md`가 예시).
   분리 기준과 각 파일의 범위는 실제 분리 시점에 문서화한다.
