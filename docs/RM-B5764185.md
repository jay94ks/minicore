# Minicore Signal 번호표

설계자 지시(2026-09-14, 메시지) - "[SP-0666DB3C] 신호 번호는 0번이면
무시(무효값), 그 외에는 (POSIX 표준과 동일한 1~22, 31번 시그널
목록)로 정의하고 `Minicore Signal 번호표`라는 이름으로 보관해둬."
SP-0666DB3C §4.2가 원래 제안했던 `SignalNumber`(Kill/Terminate/Segv/
IllegalInstruction 4종, 암묵적 0~3 값)를 이 표의 명시적 번호 체계로
대체한다 - RM-48E1E610(Syscall 할당표)과 같은 성격의 번호 현황판.

## 번호표

| 번호 | 이름 | 설명 |
|---|---|---|
| 0 | (무효값) | 신호 없음/무시 - 유효한 신호가 아님을 나타내는 값 |
| 1 | SIGHUP | 터미널 세션 연결이 끊어졌을 때(Hangup) 발생 - 주로 데몬 프로세스의 설정 리로드용 |
| 2 | SIGINT | 키보드 인터럽트(Ctrl+C)로 프로세스를 중지할 때 발생 |
| 3 | SIGQUIT | 키보드 종료(Ctrl+\)) 시 발생하며 코어 덤프(Core dump)를 남김 |
| 4 | SIGILL | 허용되지 않거나 잘못된 머신 명령어를 실행하려 할 때 발생 |
| 5 | SIGTRAP | 디버깅 브레이크포인트 등의 트랩(Trap)이 발생했을 때 |
| 6 | SIGABRT | abort() 등의 비정상 종료 함수 호출 시 발생 |
| 7 | SIGBUS | 잘못된 메모리 주소 접근(Bus error) 시 발생 |
| 8 | SIGFPE | 0으로 나누기 등 산술 연산 오류(Floating point exception) 시 발생 |
| 9 | SIGKILL | 프로세스를 즉시 강제 종료 - 잡거나(Catch) 무시할 수 없는 신호 |
| 10 | SIGUSR1 | 사용자 정의 용도로 예약된 첫 번째 신호 |
| 11 | SIGSEGV | 잘못된 메모리 영역을 참조할 때(Segmentation fault) 발생 |
| 12 | SIGUSR2 | 사용자 정의 용도로 예약된 두 번째 신호 |
| 13 | SIGPIPE | 읽는 쪽이 없는 파이프에 데이터를 쓸 때(Broken pipe) 발생 |
| 14 | SIGALRM | 알람 타이머 시간이 만료되었을 때 발생 |
| 15 | SIGTERM | 프로세스를 정상적으로 종료하기 위해 보내는 기본(Default) 종료 신호 |
| 16 | (미사용) | POSIX SIGSTKFLT 등에 대응하는 자리 - v1은 정의하지 않음 |
| 17 | SIGCHLD | 자식 프로세스가 종료되거나 중지될 때 부모 프로세스에게 전달 |
| 18 | SIGCONT | 멈춰 있던(Stopped) 프로세스를 다시 실행 |
| 19 | SIGSTOP | 프로세스를 일시 중지 - 무시할 수 없음 |
| 20 | SIGTSTP | 터미널에서 입력한 정지 신호(Ctrl+Z) |
| 21 | SIGTTIN | 백그라운드 프로세스가 터미널 입력을 시도할 때 발생 |
| 22 | SIGTTOU | 백그라운드 프로세스가 터미널 출력을 시도할 때 발생 |
| 23~30 | (미사용) | v1 범위 밖 - 필요해지면 이 표에 행을 추가해 예약 |
| 31 | SIGSYS | 잘못된 시스템 콜(Bad system call) 요청 시 발생 |

## v1에서 실제로 커널이 발생/처리하는 신호 (SP-0666DB3C §4.4 연동)

이 표의 번호 전부가 v1에서 실제로 발생 가능한 것은 아니다 - 현재
커널이 스스로 발생시킬 수 있는 것은:

- **SIGKILL(9)** — `KillArgs` syscall로 명시적 요청, 마스킹 불가.
- **SIGTERM(15)** — `KillArgs` syscall로 명시적 요청, 기본 동작은
  종료지만 핸들러로 가로챌 수 있음([갱신, 2026-09-15] ring3 진입
  자체는 PN-124C105B 완료로 더 이상 막혀 있지 않음 - 다만 유저
  핸들러를 실제로 ring3에서 호출하는 로직은 별도 후속 작업이고,
  Signal 전달 인프라 자체(`Process::pendingSignals`/체크포인트,
  PN-71E50394)가 아직 미구현이라 여전히 보류).
- **SIGSEGV(11)** — 유저 폴트 처리(SP-8B6B8D25 §2-B, SP-0666DB3C §7)가
  "진짜 잘못된 접근"이라고 판단했을 때.
- **SIGILL(4)** — #UD(잘못된 명령어) 트랩 시.

나머지 번호(SIGHUP/SIGINT/SIGQUIT/SIGTRAP/SIGABRT/SIGBUS/SIGFPE/
SIGUSR1/SIGUSR2/SIGPIPE/SIGALRM/SIGCHLD/SIGCONT/SIGSTOP/SIGTSTP/
SIGTTIN/SIGTTOU/SIGSYS)는 **번호만 이 표로 확정**해 두고, 실제로
커널의 어느 경로가 그 신호를 발생시킬지는 각 서브시스템(터미널/tty
서비스의 SIGINT·SIGTSTP, 프로세스 관리의 SIGCHLD, 알람 타이머의
SIGALRM, syscall 검증의 SIGSYS 등)이 구현될 때 그 문서에서 다룬다 -
이 문서는 "번호가 겹치지 않게 예약"하는 현황판 역할만 한다(RM-48E1E610
과 동일한 성격).

## 선행 조건 / 연관 문서

- SP-0666DB3C §4(Signal 전달) — 이 표의 번호를 `SignalNumber` enum
  값으로 그대로 사용하도록 개정됨.
- RM-32D06563(Minicore 용어 및 개념) — "SignalNumber" 항목이 이 표를
  참조하도록 갱신.
