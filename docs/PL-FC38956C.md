# 실행 계획: multiboot2 + GRUB 부팅 경로 추가

DC-427BB6B2/DS-D4E5C451에서 미룬 항목. PVH가 이미 검증된 상태(boot.S,
QA-26450C3E)라 그 자산(GDT/페이지테이블/long mode 전환/higher-half
점프)을 재사용하고, "멀티부트2 헤더 + 32비트 진입점"만 새로 추가하는
방식으로 간다.

## 선행 조건

- 없음(PVH 경로와 독립적으로 병행 가능).

## 단계

1. **boot.S 리팩터링**: 현재 `pvh_start`에 있는 "GDT 적재 → 페이지
   테이블 구성 → long mode 전환 → higher-half 점프" 로직을 별도
   서브루틴(예: `common_32bit_entry`)으로 뽑아, PVH/멀티부트2 양쪽
   진입점이 공유하게 만든다. (관계도 기록: boot.S가 PVH 전용으로
   짜여 있다는 코멘트를 이 시점에 갱신해야 함.)
2. **멀티부트2 헤더 복원**: 이전에 있던 MB2 헤더(magic
   0xe85250d6)를 다시 추가한다 - 이번엔 GRUB만 상대하므로 QEMU
   `-kernel` MB1 우회는 필요 없다(DS-D4E5C451에 남긴 사고 경위 참고).
3. **멀티부트2 진입점 작성**: `mb2_start` 32비트 진입점 - EAX 매직
   (0x36d76289) 확인, EBX(멀티부트 정보 구조체 물리주소)를 보존한
   뒤 `common_32bit_entry`로 합류.
4. **멀티부트2 정보 구조체 파싱**: hvm_start_info와 형태가 다르다
   (태그 기반 가변 길이 구조) - 메모리맵 태그(type 6)를 파싱해
   `HvmMemmapEntry`와 동일한 형태로 변환하거나, `kmain.cpp`에
   "부팅 프로토콜에 따라 다른 파서를 호출" 분기를 추가한다(매직
   값으로 PVH/MB2 구분).
5. **GRUB ISO 빌드 스크립트**: `scripts/run-grub.sh` 신설 -
   `grub-mkrescue`로 ISO 생성(grub.cfg에 `multiboot2` 명령으로
   커널 로드 지정), QEMU `-cdrom`으로 부팅. `scripts/run-qemu.sh`
   (PVH 전용)는 그대로 두고 별도 스크립트로 분리한다.
6. **검증**: QA-26450C3E의 "multiboot2 경로로 부팅된다" 체크 -
   시리얼 로그로 higher-half 진입/IDT/타이머까지 PVH 경로와 동일하게
   동작하는지 확인.

## 미결 사항

- grub.cfg의 정확한 문법/타임아웃 설정은 구현 중 확인.
