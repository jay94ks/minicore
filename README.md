# Minicore

Minicore는 x86-64를 첫 타깃으로 하는 **하이브리드 커널 기반 범용
운영체제**입니다. 이전 시도와는 목표/범위 자체가 다른 새 설계로
처음부터 다시 시작합니다.

> **현재 상태: 설계 단계.** 아직 소스 코드는 없습니다(`main` 브랜치는
> 의도적으로 비어 있음). 설계 문서와 의사결정은 저장소 파일이 아니라
> 내부 워크플로우 시스템(claude-native-workflow)의 DB로 관리됩니다.

## 개요

- **커널 형태**: 하이브리드 커널.
- **개발 언어**: C++(주 언어) + 어셈블러(하드웨어 제어/로우레벨 대응).
- **부팅 지원(x86-64)**: BIOS, PVH(QEMU), multiboot2, EFI(UEFI). 개발
  편의를 위해 `--kernel`/`--initrd` 옵션으로 이미지를 직접 넘기는 방식도
  지원하며, 시리얼 포트로 커널 로그를 수신합니다.
- **커널이 담당하는 범위**: 부팅/유저랜드 준비, 프로세스·권한 관리,
  스케줄러/SMP/인터럽트 처리, IPC 라우팅, IO 권한 부여, NUMA/메모리
  관리, 페이지 매핑·병합, 공유 메모리, 시그널, 프로세스간 공개
  인터페이스 registry, procfs.
- **ARM/RISC-V**: 설계상 고려 대상이지만 현 단계 구현 범위에서는 제외.

## 디렉터리 레이아웃 (예정)

```
minicore/
├── arch/           # 아키텍처 공통 부트 stub/bootstrap
├── libs/
│   ├── <arch_name>/  # 아키텍처별 공통 라이브러리
│   ├── libkenv/      # early 환경 C/C++ 런타임
│   ├── libkern/       # 커널/유저랜드 공용 브릿징 라이브러리
│   └── libkmm/        # 메모리 관리자 재사용 코드
├── kernel/         # 커널 본체
├── devmgr/         # 디바이스 매니저 서비스
├── fs/             # 파일시스템 서비스
├── net/            # 네트워크 서비스
└── tty/            # TTY 서비스
```

## 개발 현황 / 다음 단계

- 빌드 시스템: **CMake** (컴파일러: WSL의 clang).
- 첫 구현 대상 부팅 경로: **multiboot2** (부트로더는 기존 것을
  체인로더로 활용, 자체 구현하지 않음).
- 커널 코드는 C++ 예외를 쓰지 않고 `errno_t` 기반 에러 체계를 쓰며,
  RTTI/표준 라이브러리 지원은 부팅 초기 단계 이후 점진적으로 확장합니다.

아직 정해지지 않은 세부(프로세스간 공개 인터페이스 registry 프로토콜,
procfs 스키마 등)와 그 밖의 설계 기록은 내부 워크플로우 시스템에서
추적 중입니다.
